# 修正 45° 三维旋转晶格：预留不使用的第 0 列

日期：2026-11-12

## 问题和修正

之前将原二维矩阵有效 Column `r=0` 映射至 3D 旋转轴 `(v,0,0)`，导致四类不同矩阵之间意外重叠共享 101 个有效权重，并在后续新类写入时反复覆盖，形成一条“共享交线”。

用户指出：**矩阵增加一列不用即可**。

采取该方案：仍保持 16 个有效整数序列位置，但将三维空间中的第 0 列留空，原来的位置 `r=0..15` 映射到几何半径 `r+1=1..16`。分别使用 0°、45°、90°、135° 的整数格点方向：

| 类 | 角度 | `(dy,dz)` | 三维坐标 |
|---|---:|---|---|
| 0 | 0° | (1,0) | `(v,r+1,0)` |
| 1 | 45° | (1,1) | `(v,r+1,r+1)` |
| 2 | 90° | (0,1) | `(v,0,r+1)` |
| 3 | 135° | (-1,1) | `(v,-r-1,r+1)` |

注意：45°/135° 使用的是**方向对齐的原始整数向量** `(1,1)`、`(-1,1)`，不是单位长度坐标；因而角度正确，空间步长与水平/竖直方向不同，但不影响一对一查表或这里的实验结果。

不在几何位置 `r=0` 储存或训练任何类别特征，故不会再有公共交线。分类时仍使用每类原本的 16 个有效整数位置，不更改学习样本、数据类型或训练目标。

## 新实际结果

同一公开 UCI PenDigits 数据，按数字类别 `0→1→2→3` 逐类学习，原生整数输入、正样本类别条件 log-likelihood 表；推理不提供 Task ID。

| 当前已学习类别 | 修正：空白轴列 | 原不相交独立对照 | 旧版有共享交线 |
|---|---:|---:|---:|
| 0,1 | 96.70% | 96.70% | 96.56% |
| 0,1,2 | 84.05% | 84.05% | 83.96% |
| 0,1,2,3 | **85.91%** | **85.91%** | **85.07%** |

- 之前重叠共享的 303 个格点，现全部消除：**0 重叠**。
- 四类有效权重仍为 `4×101×16 = 6464` 个。
- 若用稀疏几何映射，未使用的轴列不分配可训练权重；几何宽度标称 17 列，真实有效位置仍为 16 列。
- 每阶段所有类别的混淆矩阵、逐类准确率、总体准确率，与先前独立保存矩阵的对照**逐项一致**，由自动测试严格断言。
- 不再需要给不同类别的旋转中心添加平移以避免共享轴；在目前四方向情况下直接绕公共轴即可。

## 实验结论

用户修正完全有效：**只需添加不使用的轴列，就可消除原实现中人为制造的交线覆盖与准确率损失。**

当前旋转晶格和独立矩阵仍具有相同的学习机制与预测行为。因此可以说几何存储实现正确，不能说纯旋转自然带来了额外的特征共享、正向迁移或更高分类准确率。
